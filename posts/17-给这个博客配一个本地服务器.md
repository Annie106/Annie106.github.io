这个博客的线上版本跑的是构建产物 `dist/`，不是仓库根目录。改完代码想立刻确认「线上会是什么样」，光双击 `index.html` 不行，得有一个真服务器。为此仓库外面常驻着两个文件：一个服务器脚本，一个双击就用的启动器。这篇写给后面接手它的人：为什么必须要服务器、这两个文件为什么不能放进仓库、出错时先看哪里。

## 为什么不能直接双击 HTML

双击打开的是 `file://` 地址。首页能渲染，但站内每篇文章的真实地址是 `/posts/&lt;id&gt;/`，那是一个**目录**，不是文件。点进文章后地址栏会变成这个目录，而磁盘上没有「访问目录就自动给 index.html」这回事：浏览器遇到 `file:///…/dist/posts/17/`，给你看的是它自带的文件列表。刷新、复制链接发给别人、从微信里点回来，全都不成立。

还有一个更直接的证据：文章页的 `&lt;head&gt;` 里写着 `&lt;base href="/"&gt;`，样式和脚本全按站点根解析。换成 `file://`，这个「根」会变成磁盘根，第一张样式表就 404，页面出来是裸的。

把这个目录请求翻译成 `index.html`，只有服务器会做。所以服务器不是「更专业的打开方式」，是这个站的非可选件。

## 为什么放在仓库外面

这两个文件跟博客内容一点关系都没有，它们是「这台机器的开发环境」。放进仓库会有三个后果：

- `dist/` 每次构建都会被清空，放进去等于放进碎纸机。
- 放在仓库根，`git status` 里就永远挂着它们，总有一天被 `git add .` 顺手带上。构建是按白名单复制的，不会把它们发布出去，但「不会误发」和「不会误提交」是两件事。
- 仓库是要被整包复制、克隆、交给别人的东西。里面塞着带本机路径的启动脚本，换台电脑就是一堆失效的绝对路径。

现在的排法是「仓库 + 工具」并排：`annie106/` 是仓库，`static-server.js` 和 `启动服务器.cmd` 放在它旁边，同一个父目录里。

这个位置不是随手放的。`.cmd` 里所有路径都从 `%~dp0` 起算，批处理里它就是「脚本自己所在的目录」，所以整个 `博客` 文件夹拖到 D 盘、换个用户名，双击照样能跑，一个字都不用改。唯一的约束是仓库目录必须还叫 `annie106`，因为脚本里写死了 `cd /d "%~dp0annie106"`。

## 两个文件各管什么

**`static-server.js`**：不到一百行，只用 Node 自带的 `http`、`fs`、`path`，没有任何依赖，也不该加依赖。它做的三件事都对着这个站的脾气：

- **目录请求补 `index.html`**。少了这一条，`/posts/17/` 就是 404，整站文章全打不开。
- **一张 MIME 表**。字体是 `.woff2`，类型给错浏览器直接不认，表现是图标集体变空白，而且不报错。
- **所有响应带 `Cache-Control: no-cache`**。改完样式按 F5 就是新的，不用清缓存猜自己看的是哪一版。

另外两个细节：只监听 `127.0.0.1`，同一局域网里的其它设备连不上，想用手机试得自己把监听地址改成 `0.0.0.0`，试完记得改回来；请求路径越出根目录会直接 403，不会被 `../` 带出去。端口默认 8000，可以 `node static-server.js 8080` 临时换，被占用时会直接说清楚，不会静默失败。

**`启动服务器.cmd`**：双击入口，一串固定流程。

- **先构建三步**：`build-site.js` → `build-posts.js` → `minify.js`。`dist/` 是产物，源码改了不重新构建，看到的还是旧的。
- **minify 可以缺**。没装 esbuild 时会跳过并打一行提示，只影响体积，不影响功能。但另外两步失败会直接停下，不会拿一个残缺的 `dist/` 去开服务。
- **把工作目录切到 `annie106\dist`**，再起服务器，等两秒打开 `http://localhost:8000/`。等这两秒是为了别让浏览器抢在服务器前面刷出一张空页。

## 怎么跑起来

前提三样：Node 18 及以上（跑构建和服务器）、Python 3.9 及以上（裁图标子集，构建会检查）、以及一次 `npm install`（只为 esbuild）。齐了以后每次都是同一个动作：

- 双击 `启动服务器.cmd`，窗口里会依次打出构建过程和访问地址。
- 浏览器自动打开 `http://localhost:8000/`，这一份就是线上那一份。
- 用完直接关窗口，或在窗口里按 `Ctrl+C`。它不是常驻服务，窗口一关就停了。

如果只想改文章、调样式，不想每次等构建，可以退一步：在仓库根跑 `node ..\static-server.js`。这时看到的是源码，文章走旧地址 `?article=`，`/posts/&lt;id&gt;/` 一定是 404，不是坏了，是产物还没生成。

## 出错先看这几条

- **点文章 404**：服务器根目录指错了。要指到 `dist/`，不是仓库根。
- **`'node' 不是内部或外部命令`**：Node 没装，或者装了没进 PATH。装完要重开一个窗口才生效。
- **端口 8000 已被占用**：上一次的窗口没关干净。先关掉，或者手动 `node static-server.js 8080`。自己换端口时，`.cmd` 里那两处 `8000` 也得一起改，否则自动打开的地址还是旧的。
- **构建那一步失败**：多半是 Python 没装好，图标子集裁不出来，或者加了字体里没有的图标。这时 `dist/` 可能残缺，别拿它下结论。
- **页面出来了但图标全空白**：`fonts/` 没复制进 `dist/`，或者字体 MIME 不对。先跑一次构建再看。
